# Sensitivity: How the Game Works

A plain-language technical guide to how *Sensitivity* is made: the graphics, sound, AI, collisions, game stages and the tools used to build and tune it. It is a **living document**: whenever a system is added or changed, this file is updated in the same change.

Related docs:
- `docs/ARCHITECTURE.md`: the code map (which file and function does what). It is written for whoever edits the code.
- `docs/LORE.md`: the story.
- `docs/CHAPTER_1_PLAN.md`: the Chapter 1 design.

*Last updated: Chapter 1 complete, with the holdout rework (door fight, window, Thimble) and Mr. Hush's clipping fixes.*

## 1. What it is built with

| | |
|---|---|
| Platform | Runs in a desktop browser (WebGL2). Nothing to install. |
| Engine | No game engine. **Three.js** (r186) for 3D, plain JavaScript modules, **Vite** to serve and bundle. |
| Assets | **None**, apart from fonts. Every model, texture, sound and piece of music is generated by code when the game starts. |
| Size | About 10,300 lines of JavaScript and CSS. |
| Run | `npm install`, then `npm run dev` (play at localhost:5173) or `npm run build` (a static site in `dist/`). |

Because everything is procedural, the download is tiny and the whole game can be changed by editing code. The trade-off is that every visual and sound has to be designed as a recipe.

## 2. The core idea: sound is sight

The world is black. The only way to see is sound. Every noise (a footstep, a door, a knock, a thrown bottle, Mr. Hush's own steps) becomes a **pulse**: a ring of light that spreads out from where the sound happened, lights up the surfaces it passes, and leaves a fading afterglow. The **same pulse is what the monsters hear**. One function, `game.sound(...)`, does both, so seeing and being heard are always the same act.

### How a pulse travels: the sound field
Sound shouldn't pass through walls, so pulses don't spread in straight lines.
- The house is laid over a **25 cm grid**. Walls and doors are drawn into it.
- For each sound, the game runs a shortest-path search (Dijkstra, 16 directions) out from the sound to get the **walking distance** to every cell. Sound flows around corners and through open doorways, and a closed door blocks the light (for hearing it muffles instead).
- The search stops at the sound's own radius, and results are cached, so a footstep costs well under 2 ms. (An early version took 70 ms per sound and caused visible freezes; it was fixed by making the search expand each cell only once.)
- Up to **24 pulses** can be alive at once. Their distance maps are packed into one texture the graphics card reads.

### How a pulse looks
For each point on a surface, the shader works out how long ago the ring passed it:
1. **Flash:** full brightness for about 0.6 s after the ring goes by.
2. **Afterglow:** a quick drop to a dim glow that lingers.
3. **Fade:** after a few seconds it eases away.

A knock is bright from 0.25 to 0.7 s, dim until about 3 s, and gone by 5 s. Your own sounds peak slightly lower than the world's. A very faint 3 m glow around the player means standing still isn't totally black.

Colours tell you the source: **ice white** for you, **red** for Mr. Hush, **amber** for the house (nightlight, drips, clock), and **pale blue** for lights and the TV.

## 3. Graphics pipeline

Every frame goes through these stages:

1. **G-buffer pass.** All world geometry is drawn once into three images at the same time (multiple render targets): base colour, surface direction and depth, and *reveal light* plus highlight. Every world object uses one custom material (`revealMaterial`) that adds up the light from all active pulses, using the sound-field distances above. Surfaces also get procedural patterns (floorboards, wallpaper, tile, fur, blood) drawn in the shader, so no textures are needed for them.
2. **Edge pass.** A full-screen pass finds outlines where depth or surface direction jumps, and draws them in the colour of whatever light reached them. This is what gives the glowing-line look. Interactable items can glow amber here (the "evidence" highlight).
3. **Anti-aliasing (FXAA)** smooths the lines.
4. **Bloom** makes bright lines bleed light. It's skipped on Low quality.
5. **Final grade:** tone mapping, film grain, colour fringing, the fear vignette that pulses with your heartbeat, red flashes, the out-of-breath tunnel vision, fades, and the **night-vision mode** of the baby monitor.

Other visual pieces:
- **Lightning** briefly lights everything through the windows.
- The **baby monitor** renders the house from security cameras with an infrared ambient light, then applies the green night-vision grade, scanlines and static.
- **Dawn** slowly raises an ambient light so you finally see June's room.
- Small things: drifting dust, glass that only shimmers where sound passes, Mr. Hush's faint button-eye glints in the dark.

### Keeping it fast
- The number of shaded pixels is capped (2.4 million), times the Quality setting (Low 60%, Medium 80%, High 100%).
- **Adaptive resolution:** if the frame rate drops below about 48 FPS, the render resolution steps down 10% at a time (to 50%), and steps back up after ~20 s of smooth play.
- The surface shader only loops over pulses that are actually alive.
- All textures and shaders are uploaded when the game loads, so looking into a new room never stutters.
- An optional **FPS counter** is on by default (Settings).

## 4. The world

- **The house** (17 × 14 m, one storey, 2.7 m ceilings) is built in code by `House.js`: walls with door, window and arch openings; floors and ceilings per room; trim; windows; eight hinged doors; and the furniture.
- **Furniture** comes from recipe functions (`props.js`): sofas, beds, a wardrobe, a grandfather clock, a CRT TV, kitchen counters and so on. Each is built from boxes, cylinders, spheres, lathed shapes and tubes. Pieces sharing a material are merged into one mesh, so the whole house draws in a few calls.
- **Canvas textures** are painted in code: June's crayon drawings, blood, Diane's scratched writing, photos, the clock face, a poster, TV static.
- **Moving parts** are separate objects: doors, the drawers you search, June's rocking chair, the window shutters, thrown objects, the baby monitor.
- **Floor surfaces** (carpet, rug, wood, tile, glass, grass) set how loud footsteps are. Some floorboards creak. Broken glass becomes a loud patch of floor.

## 5. The player

| Move | Speed | Footstep noise |
|---|---|---|
| Creep (C, hold or toggle) | 1.15 m/s | quietest |
| Walk | 2.15 m/s | normal |
| Run (Shift) | 4.3 m/s | very loud, drains stamina |

- Noise is multiplied by the floor: carpet ×0.6, rug ×0.5, wood ×1, tile ×1.3, glass ×2.2, grass ×0.7.
- **Knock (Q)** makes a sound on purpose to see, with a 0.85 s cooldown so it can't be spammed.
- **Breath (Space):** within 4.5 m of Mr. Hush your breathing is audible to him. Hold it (about 6.5 s, or 10 s while hidden). Running out makes you gasp, which he hears, and your vision tunnels as you near passing out.
- **Doors:** tap E to open fast and loud, or hold E to open slowly and quietly.
- **Hiding:** wardrobe, linen closet, under the bed. The camera glides in and out instead of teleporting.
- **Throwing:** pick up bottles and blocks and throw them as decoys. A throw only counts if the mouse press started during play, so clicking a menu button never throws.
- **Camera:** head bob (optional), a lean when strafing, fear sway, shake (reduced by the *Reduce flashing* setting), and a "forced look" for grabs and cutscenes.

## 6. Collisions

- **Player vs world:** the player is a circle (radius 0.28 m) pushed out of box colliders and out of each door's rotated box (`resolveCircle`). Colliders are boxes registered by the house and each piece of furniture.
- **Player vs Mr. Hush:** you can't get closer than 0.75 m to his centre. If he walks into you, you're shoved aside but never into a wall.
- **Mr. Hush vs world** (he is ~1.25 m wide, ~1 m deep and 2.6 m tall):
  - **Pathfinding margins:** his routes keep about 0.6 m from walls, 0.5 m from tall furniture and 0.36 m from low furniture (his belly passes over low things).
  - **Doorways:** paths go through the middle of each doorway, square to the wall. Near a doorway he **squashes through**: his stuffed body narrows to ~0.85 m, his arms tuck in, and he slows down.
  - **Push-out:** every frame his body is pushed out of walls and furniture as a safety net for stumbles, corners and teleports.
  - **His chair:** Mom's armchair is stretched so he actually sits in it.
- **Grab placement:** when he grabs you, he's always placed 1.15 m in front of you on a clear spot with no wall between. This keeps his face in view and the camera steady.

## 7. Sound and hearing

### The audio engine
- All sound effects are **synthesised when you click "Begin"** (about 0.8 s): footsteps per surface, creaks, doors, knocks, glass, his steps, growls and sniffs, the jumpscare, thunder, rain, wind, heartbeat, breath, clock, drips, tape hiss, static and more. They're built from noise, filters and modal resonators (`SoundBank.js`, `dsp.js`).
- **Mixing buses:** effects, music, ambience, voice and UI, through a compressor, with a convolution reverb.
- **3D audio:** sounds are positioned around you, and walls between you and a sound muffle it with a low-pass filter. Headphones recommended.
- **Music-box lullaby:** played note by note from a melody table, with optional radio filtering (the monitor's talk-back) and wobble.
- **Mr. Hush's voice:** a positional hummed lullaby that cuts off when he hears something.
- **Heartbeat** speeds up with fear.

### How Mr. Hush hears
- Every `game.sound` from the player or from objects reaches him through the same grid, with closed doors adding a muffling cost.
- A sound reaches him if its walking distance is within its radius × 1.25. Intensity is how close it got.
- Loud sounds above 0.42 intensity start a **hunt**; softer ones make him **investigate**. "Soft" sounds (creeping, breathing, slow doors) need 0.75.
- Ambient house sounds and his own sounds are never heard by him. Thrown objects are decoys he goes to check.

## 8. Mr. Hush's behaviour

| State | What he does |
|---|---|
| Dormant | Asleep in the armchair. Noise builds up a "wake" meter, and his head lifts as it fills. A loud enough noise, or taking the key, wakes him. |
| Wander | Humming, walking between rooms, drifting toward the room you're in. |
| Investigate | Walks to a sound he heard. |
| Search | Sniffs and looks around where he lost you. |
| Check | Opens hiding spots, favouring ones you've used. If you're inside and not holding your breath, he finds you. |
| Hunt | Fast (3.3 m/s, you run at 4.3). Tracks you while you're moving within 7 m. Freeze, creep or hide to break the trail. |
| Grab | Holds you; you mash A/D to break free. |
| Stunned | 2 s after you break free: he staggers and clutches his head. |

Systems that keep him a threat:
- **Menace** grows while he's far from you and steers him your way.
- **Scent:** standing next to him for 2.5 s gives you away.
- **Re-catch rule:** being grabbed again within **45 s** of escaping is fatal.
- **Giving up:** after an empty check he leaves for 15 s, so hiding and holding your breath works.

He was tuned with bot simulations: a careful bot survives three minutes about half the time.

### Animation
His body is a jointed rig of procedural shapes (lumpy lathed body, long arms with needle claws, sewn button eyes, a jaw that opens into teeth). `animateHush` blends pose channels: walk, run, listen, hunch, sit, grab, jaw, stagger, look, reach, turn, sniff, stir and squeeze.
- **Springs** give the torso, neck and arms a heavy, late, overshooting motion.
- **Gait:** each footfall has a dip. Running leans forward with the jaw hanging open, and he leans into turns.
- **Idle:** breathing and random head twitches.
- **Sounds:** his head snaps toward what he hears, and sniffs lift his snout in short pulls.

### Pathfinding
A* over the same 25 cm grid, with obstacles grown by the margins in section 6, then smoothed into straight lines, then routed through doorway centres. A connectivity test (every waypoint, hiding spot and holdout node to every other) must pass whenever furniture moves.

## 9. The holdout (3:00 to 6:00 AM)

A FNAF-style finale in June's room. You sit; you can look around but can't walk. Each in-game hour is 80 seconds, and it gets harder each hour. **If anything gets in, you die.**

- **Mr. Hush** moves along a graph of rooms (living room, foyer, kitchen, hallway, June's door, the back door, the yard and June's window). Each hour he moves more often and attacks sooner.
- **Baby monitor (Space, then 1/2/3):** night-vision feeds of three rooms. It drains battery while raised and shows static when he's near the camera. **L with the monitor up** plays the lullaby in that room to lure him there.
- **The door:** it starts closed. After a warning (sniffing, scratching, the handle) he forces it. The camera turns to the door and **one key (W/A/S/D) pops up at a time**: the right key pushes it back, a wrong one lets him in further. Win and the door slams; he bangs on it 3–5 times and leaves. Bot-tuned: you need about 2, 2.5 and 3 correct presses a second at 3, 4 and 5 AM.
- **The window:** a faint tap is the only warning. Then you have 2.5 s (1.75 s by 5 AM) to look at it and hold the mouse to shut the shutters, and you must keep holding for 2.4 s while he tries them.
- **Thimble:** the doll's agitation rises all night. You see it in his **shadow growing up the wall**, the chair rocking harder, and a slow heartbeat thud from the chair that speeds up (each beat throws a red pulse that lights his shadow). **L with the monitor down** winds the music box and calms him, but it's Mr. Hush's song, so it draws him to June's room for 16 s. At full agitation Thimble kills you.
- **Dawn:** he walks back to his chair, the room fills with grey light, and the last tape is in the monitor.

In a full-night bot test, a player pressing 3.2 keys a second and singing at 65% agitation survives with about 4–7 door attacks and 1–4 window visits.

## 10. Stages, flow and saving

- **Game states:** boot → menu (a live scene of Mr. Hush in his chair) → prologue → play ⇄ cutscene → holdout → (dawn) play → end; and dead. Pause, documents and menus are overlays.
- **Chapter 1 flow:**
  1. The foyer. Find June's room.
  2. Find the key in Diane's nightstand, which wakes him.
  3. Get to June's room; the monitor is dead.
  4. Get batteries from the kitchen.
  5. Return and switch on the monitor (cutscene).
  6. The holdout.
  7. Dawn and the final tape.
  8. End screen.
- **Checkpoints:** the foyer, Diane's bedroom, the kitchen, and June's room at 3:00 AM. Dying restarts from the last one.
- **Timed story beats** run on the game's own clock (`chapter.at`), so they pause with the game and stay in sync with test simulations.
- **The house remembers:** open doors, thrown objects and broken glass stay as you left them, and he investigates the disturbances.
- **Objectives** are always on screen; a new one shows large for 7 s, then settles small. An **inventory** on the right shows what you carry (key, batteries).
- **Evidence:** 17 documents and tapes. An item stays dark until a sound you make reaches it, then glows for 4.5 s and fades. Read it in an overlay, or play tapes as subtitles while you keep moving. Tab opens the evidence screen.
- **Saving:** browser localStorage holds settings and progress (checkpoint plus evidence found). Settings have a migration counter for changed defaults.

## 11. Interface

- All menus and the HUD are HTML/CSS layered over the 3D canvas: boot screen, main menu, prologue, pause (with the objective, location, evidence count and a controls list), settings (General and Controls tabs), evidence, document viewer, death and end screens.
- **HUD:**
  - objective;
  - interaction prompt with hold bar;
  - hints and subtitles;
  - noise meter;
  - breath bar;
  - struggle;
  - door-fight panel;
  - inventory;
  - holdout clock;
  - tape cassette;
  - FPS counter;
  - "Click to continue" layer.
- **Look:** dark analog horror. Fonts: IM Fell English, IBM Plex Mono, Special Elite, Reenie Beanie, Homemade Apple, VT323. No emoji, no glass panels, no rounded app buttons.
- **Controls** are rebindable. Gameplay code asks for *actions* (`interact`, `knock`, `breath`...), never raw keys. Ctrl is avoided as a default because Ctrl+W closes the browser tab.
- **Settings:**
  - mouse sensitivity and invert;
  - FOV;
  - head bob;
  - creep hold/toggle;
  - brightness;
  - quality;
  - adaptive resolution;
  - FPS counter;
  - film grain;
  - four volume sliders;
  - subtitles and their size;
  - reduce flashing;
  - reset to defaults.
- **Pause:** Esc pauses and Esc resumes. Browsers only re-capture the mouse after a click, so "Click to continue" holds the game until you click. Switching tabs pauses and silences the game.

## 12. How it is built and tested

- **Headless testing.** The cloud machine has no graphics card, so the game has a **manual mode** (`?dev&manual`). The test harness steps the simulation itself (`simulate(seconds)`) and renders single frames on demand (`renderFrame()`), driven by Playwright and Chromium's software renderer.
- **Bots instead of hand-testing.** Mechanics are tuned by scripted players: an evasive player in the house, door-fight bots at different key rates, full-night holdout bots, hide-and-hold-breath bots, and re-catch timing checks.
- **Measurements:** sound-field cost per pulse, frame-time spikes, pulse brightness curves (average screen brightness over time), Mr. Hush's distance to walls over three minutes, and camera stability during grabs.
- **Screenshots** with an even light let us review models, poses and UI.
- **Regression set** after every change: re-catch rule, hearing ranges, hiding, all checkpoints, evidence reachability, pathfinding connectivity, holdout bots.
- `npm run build` must pass before any commit.
